## Finding / smallest necessary server addition

Existing `GET /api/game/character-creation-catalog` (legacy alias also exists) already supplies eligible Sorcerer level1 spell IDs and labels. It does **not** supply starting-level support, per-level additions, Metamagic options or stable subclass IDs. Do not hardcode these in React or copy the PHB class table into DEFAULT_CATALOG.

Add one **optional typed** `sorcerer_starting_creation` field to the existing catalog response, populated on the server, with:
- `supported_starting_levels`: currently [1,2,3], bounded to the existing accepted Sorcerer adapter support, never all20 source rows.
- `level_2`: `prepared_spell_count`, `prepared_spell_ids`, `metamagic_count`, `metamagic_options`.
- `level_3`: `prepared_spell_count`, `prepared_spell_ids`, `subclass_options: [{id,name}]`.
- `effects_pending_by_level`: keys "1", "2", "3" with informative pending-effect lists.

Counts are source-table differences (2 new ordinary spells at each step, 2 Metamagic selections at2); option IDs come from the same `SPELLS_CATALOG['Sorcerer']['spells_level_1']`, class-table metamagic_options/subclass_options used by the core. Pending lists come from existing `progression_effects_pending('Sorcerer', level)`. Copy data for projection, do not mutate tables. Reuse existing spell metadata for labels by ID. No new endpoint, preview session, grants, spendable Sorcery Point projection, source-content expansion or generic capability framework. Current eligible ordinary choices remain level1-catalog choices, not every spell available to tabletop Sorcerer3.

Owners: `ai-dnd/api/dnd_2024_rules.py:get_character_creation_catalog` (~1047); `character_progression.py` table/pending helper (pure projection helper may live here to avoid duplicating rules); `api/schemas.py:CharacterCreationCatalogResponse`; published OpenAPI and generated clients. If dnd_2024_rules imports progression for projection, import locally in the catalog function to avoid its existing progression→rules import cycle. New catalog schema must be typed despite surrounding legacy Any-valued sections. Regenerate with existing Orval path.
