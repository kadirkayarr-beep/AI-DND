SONRA:

### Eğer mevcut engine capability yeterliyse

Yalnızca mevcut yetkili arayüzleri kullanarak küçük bir set interaktif event sonucu ekle.

Öncelik:

GREEN
→ yalnızca atmosfer

BLUE
→ geçici/interaktif sahne

ORANGE
→ mevcut engine tarafından doğrulanabilen küçük ve kalıcı sonuçlar

RED
→ bu aşamada yalnızca mevcut engine gerçekten destekliyorsa

Örnek güvenli sonuçlar, yalnızca mevcut API destekliyorsa:

- oyuncunun bir NPC ile konuşması sonucunda mevcut relationship/memory sistemine event yazılması
- mevcut inventory interface'i üzerinden doğrulanmış bir eşya kazanımı/kaybı
- mevcut gold interface'i üzerinden doğrulanmış ekonomik sonuç
- mevcut quest interface'i üzerinden doğrulanmış thread/quest ilerlemesi

Bunları örnek olarak değerlendir; mevcut API desteklemiyorsa yeni gizli mutation yazma.

### Eğer engine capability yeterli değilse

IMPLEMENTATION YAPMA.

Özellikle:

- `game.py` değiştirme
- ambient_event_catalog içine gizli state mutation koyma
- doğrudan DB/session objesine mutation ekleme
- Qwen çıktısını state authority yapma
- yeni paralel event/quest/inventory engine oluşturma
- mevcut interface'i bypass etme

Bunun yerine raporla:

1. Eksik engine capability nedir?
2. Neden mevcut interface yeterli değil?
3. Gereken minimum authoritative interface nedir?
4. Bu interface hangi state'i değiştirebilir?
5. Persistence nasıl yapılmalıdır?
6. Hangi deterministic testler gerekli?
7. `game.py` değişikliği gerçekten kaçınılmaz mı?

Ve DUR.
