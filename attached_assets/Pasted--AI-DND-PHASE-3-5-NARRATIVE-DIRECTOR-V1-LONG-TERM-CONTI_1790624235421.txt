======================================================================
PRIMARY EXPERIENCE GOAL
======================================================================

Current narration is intentionally conservative because canonical safety has
been prioritized.

Narrative Director V1 should preserve that safety while making the OUTPUT feel
like a high-quality AI tabletop adventure.

A player should be able to:

- enter a tavern
- speak to an NPC
- leave
- have several unrelated adventures
- return much later
- meet that same NPC again

and the story should remember:

- who the NPC is
- which exact NPC this was
- where they met
- what they discussed
- promises made
- arguments
- favors
- discoveries
- relevant past events

without dumping the entire campaign transcript into Qwen.

The story must feel continuous.

======================================================================
CRITICAL PROBLEM #1
CANONICAL FACTS VS NARRATIVE TEXTURE
======================================================================

Create an explicit distinction between:

A. CANONICAL REALITY
B. NARRATIVE CONTINUITY
C. TEMPORARY NARRATIVE TEXTURE

--------------------------------------------------
A. CANONICAL REALITY
--------------------------------------------------

Owned by Python.

Examples:

- player HP
- inventory
- equipment
- current canonical location
- canonical NPC existence
- NPC identity
- combat
- quest status
- world metadata
- doors
- items
- discovered places
- mechanical outcomes
- skill-check result
- weather value
- time_of_day value

Qwen cannot change these.

--------------------------------------------------
B. NARRATIVE CONTINUITY
--------------------------------------------------

Persistent descriptive facts that may improve storytelling but have NO
mechanical authority.

Examples where safe:

- an established NPC speaks slowly
- a canonical tavern smells of smoke and spices
- an NPC habitually taps the counter while thinking
- an established room has cracked wooden shutters
- an NPC previously made a joke
- two characters previously argued
- the player previously asked an NPC about a subject
- an NPC previously expressed suspicion in dialogue

These MAY persist as narrative memory.

They must NEVER override canonical state.

Example:

Narrative memory:
“Kasim tends to clean glasses while talking.”

Fine.

Narrative memory:
“Kasim owns a legendary sword worth 5,000 gold.”

NOT acceptable unless canonical.

--------------------------------------------------
C. TEMPORARY NARRATIVE TEXTURE
--------------------------------------------------

Qwen may freely add low-risk atmospheric detail that is not treated as
persistent game reality.

Examples:

- fire crackles
- floorboards creak
- distant conversation
- candle smoke
- wind through trees
- rain striking windows
- vague crowds
- distant carts
- background laughter

These are presentation.

They must NOT automatically become:

- inventory
- NPCs
- quests
- locations
- interactive objects
- secrets
- money
- mechanics

======================================================================
NARRATIVE FREEDOM RULE
======================================================================

Qwen MUST be given more creative freedom than the current conservative
narrator.

It may creatively describe:

- sensory detail
- light
- sound
- smell
- temperature
- architecture
- expressions
- body language
- pacing
- atmosphere
- environmental texture
- minor non-interactive background activity

provided the output does not contradict canonical state.

Example canonical input:

location = Tavern
environment = tavern
time = evening
weather = rain
NPC = Kasim
player approaches Kasim

Good narration may say:

Rain taps steadily against the tavern windows. Warm light from the hearth
catches on the wet shoulders of your cloak as you cross the uneven wooden
floor. Kasim notices you approaching and stops polishing the glass in his
hand.

This does NOT require every decorative detail to exist mechanically.

======================================================================

Qwen cannot independently establish:

- major new NPC
- canonical NPC identity
- canonical location
- quest
- quest objective
- item ownership
- inventory changes
- gold
- damage
- healing

- faction membership
- relationship score
- discovered secret
- locked/unlocked state
- spell effect
- XP
- level
- canonical weather change
- canonical time advancement
- death
- permanent injury
- canonical reward

unless Python already established it.

======================================================================
PLAYER AGENCY
======================================================================

Narration must NOT decide major player actions.

Bad:

“You draw your sword and charge the guard.”

if the player did not choose that.

Bad:

“You realize Kasim is lying and immediately distrust him.”

if no canonical Insight result established that.

Good:

“Kasim’s gaze lingers on you for a moment longer than before.”

The player decides what that means.

Narration may describe involuntary sensory experience:

- hearing
- seeing
- feeling heat/cold
- pain already caused canonically

but should not decide:

- player intentions
- beliefs
- moral decisions
- dialogue choices
- major actions

======================================================================
MEMORY ARCHITECTURE
======================================================================

Narrative memory must be STRUCTURED.

Do not solve memory by simply sending the full transcript forever.

Create distinct memory layers.

At minimum:

1. RECENT TURN MEMORY
2. STORY SUMMARY MEMORY
3. ENTITY MEMORY
4. NPC INTERACTION MEMORY
5. LOCATION CONTINUITY MEMORY
6. QUEST MEMORY
7. UNRESOLVED THREAD MEMORY
8. NARRATIVE STYLE MEMORY

Each layer has a different purpose.

======================================================================
1. RECENT TURN MEMORY
======================================================================

Keep the most recent relevant exchanges verbatim or near-verbatim.

Purpose:

- conversational continuity
- immediate action context
- avoid characters forgetting what was said 20 seconds ago

Do not keep unlimited raw turns in the model context.

Use a bounded recent window.

Determine the correct size after inspecting context/token capacity.

======================================================================
2. STORY SUMMARY MEMORY
======================================================================

Create a persistent compact campaign summary.

This must NOT be one giant paragraph that becomes increasingly useless.

Prefer structured sections.

Conceptual example:

CURRENT ARC
RECENT EVENTS
IMPORTANT RELATIONSHIPS
CURRENT LOCATION
UNRESOLVED THREADS
MAJOR DISCOVERIES
PLAYER-RELEVANT HISTORY

Update incrementally.

Do not regenerate the entire campaign summary from scratch every turn.

======================================================================
SUMMARY FACT SAFETY
======================================================================

The summary must distinguish:

CANONICAL FACT
NARRATIVE CONTINUITY FACT
UNRESOLVED / UNCERTAIN

Never promote uncertain narration into canonical truth.

Example:

Canonical:
Player defeated Bandit npc_87.

Fine.

Narration:
Kasim “seemed worried.”

May be stored as narrative continuity.

Narration:
Kasim secretly belongs to the royal assassins.

Do NOT store as fact unless canonical state supports it.

======================================================================
3. ENTITY MEMORY
======================================================================

This is CRITICAL.

NEVER use display name as identity.

Every persistent entity must use stable canonical identity.

Examples:

npc_id
location_id
quest_id
objective_id
item_id where available

Memory entries must reference IDs.

Names are presentation only.

======================================================================
SAME-NAME ENTITY SAFETY
======================================================================

AI-DND MUST correctly handle:

NPC:
Arin — npc_001
Arin — npc_058

Quest:
The Missing Child — quest_12
The Missing Child — quest_91

Location:
Old Mill — location_A
Old Mill — location_B

These must NEVER be merged merely because display text matches.

Internally build context such as:

ENTITY:
npc_001
display_name: Arin
role: blacksmith
last_known_location: Eastgate

ENTITY:
npc_058
display_name: Arin
role: traveler
last_known_location: Forest Camp

Do not show IDs to the player unless debugging.

======================================================================
AMBIGUOUS REFERENCES
======================================================================

If the player says:

“Arin’e gidiyorum.”

and two known Arins are plausible:

DO NOT guess.

Resolve using:

1. current location
2. current scene participants
3. recent conversational focus
4. canonical availability
5. explicit aliases

If still ambiguous:

ask a natural clarification.

Example:

“Eastgate’teki demirci Arin’i mi, yoksa orman kampında tanıştığın Arin’i mi
kastediyorsun?”

Do not merge memories.

======================================================================
4. NPC INTERACTION MEMORY
======================================================================

Each canonical NPC should have compact long-term interaction memory.

Potential memory types:

- first meeting
- most recent meeting
- important dialogue topics
- promises
- threats
- favors
- known player facts disclosed to that NPC
- NPC facts disclosed to the player
- unresolved conversations
- relevant emotional/social continuity where already supported

Do NOT store every line.

Store meaningful interaction events.

======================================================================
NPC KNOWLEDGE BOUNDARIES
======================================================================

NPC memory must not become global omniscience.

If NPC A learned something:

NPC B does NOT automatically know it.

Memory must be scoped to:

npc_id

or a canonical shared knowledge mechanism if one exists later.

======================================================================
NPC VOICE CONTINUITY
======================================================================

Narrative Director should give each recurring NPC a consistent speaking
style when enough context exists.

Possible descriptors:

- terse
- formal
- sarcastic
- cautious
- warm
- blunt

Use existing canonical/personality information first.

Narrative continuity may record established style.

Do not randomly change personality every meeting.

======================================================================
5. LOCATION CONTINUITY MEMORY
======================================================================

When revisiting the same canonical location, narration should remember
previously established safe descriptive continuity.

Example:

First visit:
“Three narrow windows overlook the muddy road.”

Return 30 turns later:
the tavern should not suddenly have a marble glass atrium unless canonical
state changed.

Store only low-risk continuity facts.

Location memory keyed by canonical location ID.

Never merge same-name locations.

======================================================================
6. QUEST MEMORY
======================================================================

Use canonical quest_id.

If quest lifecycle is currently unavailable:

do NOT invent it.

Narrative Director may remember discussions related to a possible task, but
must not label it ACTIVE unless canonical Quest Outcomes confirms it.

Two quests with identical titles remain separate by quest_id.

Context should include:

quest_id
title
giver ID
status
active objectives
relevant progress

only if canonical.

======================================================================
7. UNRESOLVED THREAD MEMORY
======================================================================

Create a lightweight narrative thread system.

Examples:

- NPC asked the player to return later
- mysterious symbol was noticed
- player promised to ask Kasim about something
- player is searching for information
- conversation was interrupted

These are NOT automatically quests.

They are narrative continuity threads.

Each should have:

thread_id
related_entity_ids
summary
status:
    open
    resolved
    stale
last_referenced_turn

They must never grant rewards or mechanics.

======================================================================
THREAD DUPLICATION
======================================================================

Before creating a new thread:

check whether an equivalent unresolved thread already exists.

Do not generate:

“Mysterious symbol”
“Mysterious symbol investigation”
“Strange symbol mystery”
“Question about symbol”

as four separate threads for the same event.

Deduplicate by entity relationships + event origin + normalized subject.

======================================================================
DETERMINISTIC DUPLICATE DETECTION
======================================================================

Where practical, add a lightweight server-side similarity check.

Do not require a new external vector database for V1.

Possible safe techniques:

- normalized sentence matching
- repeated n-grams
- phrase frequency
- recent-opening equality
- high lexical overlap

Do not reject prose because ordinary words repeat.

Target obvious repetition.

======================================================================
MODEL RETRY SAFETY
======================================================================

Current model call limits must remain respected.

Do NOT simply add unlimited narrator retries.

Inspect the current call budget.

If a repetition rewrite would exceed the allowed per-turn model calls:

do not exceed the cap.

Prefer prevention through context/prompt construction.

Any bounded retry strategy must remain inside existing call safety.

======================================================================
AVOID AI WRITING TICS
======================================================================

Narrator instructions should discourage constant reuse of patterns such as:

- “For a moment...”
- “The air is thick with...”
- “You can't help but...”
- “A sense of... washes over you.”
- “Little do you know...”
- “The weight of...”
- constant “suddenly”
- constant “almost as if”
- constant dramatic ellipses
- every NPC smirking/chuckling
- every scene beginning with weather
- every response ending with a rhetorical hook

Do not ban these absolutely.

Prevent overuse.

======================================================================
LONG-TERM MEMORY RETRIEVAL
======================================================================

Do not send ALL memory every turn.

Build relevance selection.

Potential scoring factors:

- entity currently present
- entity explicitly mentioned
- current location
- active canonical quest
- unresolved thread
- recent interaction
- semantic/topic overlap
- recency
- importance
- direct relationship to current action

Retrieve only relevant memories.

======================================================================
MEMORY PRIORITY
======================================================================

Suggested priority:

1. canonical current state
2. current scene entities
3. immediately recent turns
4. directly referenced entity memory
5. active relevant quest/objective
6. unresolved relevant threads
7. relevant story summary
8. older narrative continuity details

Canonical state always wins on contradiction.

======================================================================
MEMORY CONFLICT RESOLUTION
======================================================================

If memory contradicts canonical state:

canonical state wins.

Example:

Old narrative memory:
“Kasim is at the tavern.”

Current canonical state:
Kasim is in the market.

Narrator receives:

CURRENT CANONICAL:
market

Old location memory must not force him back into tavern.

Either update or mark old memory historical.

FINAL PRINCIPLE
======================================================================

The game should be allowed to WRITE LIKE A STORY without being allowed to
MAKE UP THE RULES.

Canonical reality should remain strict.

Narrative expression should become rich.

Memory should be selective but reliable.

Identity must be ID-based, never name-based.

A recurring character should feel like the SAME PERSON.

A revisited place should feel like the SAME PLACE.

Two people with the same name must remain TWO DIFFERENT PEOPLE.

Two quests with the same title must remain TWO DIFFERENT QUESTS.

Important history should survive.

Irrelevant noise should fade.

The narrator should not repeat itself constantly.

The player should feel that the world remembers them.
