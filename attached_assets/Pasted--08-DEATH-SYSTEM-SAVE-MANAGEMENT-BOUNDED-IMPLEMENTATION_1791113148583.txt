#08 — DEATH SYSTEM + SAVE MANAGEMENT
BOUNDED IMPLEMENTATION

The #08 READ-ONLY audit is complete.

The NPC/monster 0 HP source conflict has now been explicitly resolved.

Selected policy:

POLICY A — 2024 DEFAULT MONSTER DEATH

- Ordinary resolved damage reducing an NPC/monster to 0 HP makes it DEAD.
- NPCs/monsters do not receive player-style Death Saving Throws.
- Verified monster-specific survival traits may override this only when
  their mechanics are actually supported.
- Explicit nonlethal/knockout behavior is separate and must not be
  simulated by leaving lethal 0-HP damage as Unconscious.
- No model or frontend may decide whether an NPC survives.

The implementation must now proceed within the bounded scope below.

============================================================
ABSOLUTE ARCHITECTURAL RULES
============================================================

Python remains the sole authority for:

- HP

- unconsciousness

Death mechanics and save deletion must require 0 model calls.

- rollback system

Reuse existing owners.

============================================================
1. PLAYER DEATH — 0 HP
============================================================

Preserve the existing player Death Save system where it already matches
the 2024 rules.

Verify and implement the missing authoritative boundaries identified in
the audit:

- 0 HP enters Unconscious when applicable.
- Death Saving Throws occur only under the correct conditions.
- Natural 1 = two failures.
- Natural 20 = regain 1 HP.
- Three successes = Stable.
- Three failures = Dead.
- Damage at 0 HP produces the correct Death Save consequences.
- Critical hits at 0 HP produce the correct additional failure behavior.
- Massive damage / instant death is resolved before ordinary Death
  Saving Throw progression where applicable.
- Damage reducing HP to 0 must not accidentally apply death-save
  consequences twice.
- HP maximum reaching 0 must use the authoritative death boundary.
- Healing from 0 HP exits the correct state and does not create
  duplicate recovery.
- Temporary HP must not incorrectly prevent the 0-HP boundary.

Do not create a second damage/death resolver.

The existing damage/attack owners remain authoritative for damage math.

The Death System consumes their resolved result.

============================================================
2. UNCONSCIOUS CONDITION
============================================================

Preserve the real Unconscious condition.

Ensure:

- illegal actions are rejected
- movement/action restrictions are respected
- relevant attack modifiers remain authoritative
- relevant saving throw effects remain authoritative
- existing Initiative ownership remains intact
- unconsciousness does not cause an Initiative reroll
- healing/recovery returns the actor to the correct state
- dead actors cannot continue acting

Do not remove Unconscious merely because NPC lethal damage now produces
Dead.

Unconscious remains valid for player characters and explicitly
supported nonlethal/knockout outcomes.

============================================================
3. NPC / MONSTER 0 HP — POLICY A
============================================================

Change the existing ordinary NPC/monster lethal boundary:

OLD:
ordinary NPC damage → 0 HP → Unconscious

NEW:
ordinary NPC/monster damage → 0 HP → Dead

Use one authoritative handoff.

Known existing locations include:

- weapon_attack.py
- game.py
- monster_combat.py
- initiative/combat lifecycle integration

Do not create independent death handling for different damage sources.

Inner Radiance and other damage sources must use the same authoritative
NPC death policy.

Do not add player-style Death Saves to monsters.

Do not add generic Stable recovery to monsters.

Do not infer monster survival from narrative importance.

Do not fabricate Monster Manual abilities.

If a verified monster stat block contains a supported survival mechanic,
that mechanic may override ordinary death only through an explicit
supported owner.

Unsupported monster-specific mechanics remain unsupported.

- existing combat cursor/lifecycle ownership remains intact

- combat closure uses existing Combat Lifecycle ownership

Do not redesign initiative.

Do not redesign Monster Combat.

Update only the affected contracts/tests from #07 that explicitly

Preserve genuine Unconscious tests.

============================================================
6. STABLE RECOVERY + CAMPAIGN TIME
============================================================

Implement the missing Stable recovery integration using the existing
Campaign Time owner.

Do NOT create another scheduler.

A Stable player at 0 HP who remains unhealed must receive the
authoritative recovery behavior after the rules-defined random duration.

The existing rules/audit establish the duration as 1d4 hours.

Requirements:

- Python owns the timing.
- Existing Campaign Time owns progression.
- RNG is authoritative and persisted.
- Save/resume preserves the pending recovery.
- Process restart does not lose it.
- Closing the application does not advance real-world time.
- Advancing campaign time resolves it exactly once.
- Replay of the same action does not reroll it.
- Rollback restores the correct prior timing/RNG state.
- Long actions/travel/rest/event progression interact through the
  existing Campaign Time system.
- No second scheduler is introduced.

Do not automatically reveal unknown aftermath merely because time passed.

============================================================
7. STABILIZATION / HELP / MEDICINE
============================================================

- resolve canonically in Python
- stop Death Saving Throw progression
- preserve correct HP/state
- persist correctly
- replay idempotently

Failed stabilization must not silently stabilize the character.

============================================================
