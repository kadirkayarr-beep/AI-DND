==================================================
2. CAMPAIGN START TIME
==================================================

Campaign Time ilk dünya sahnesi oluşturulduğu anda başlar.

Mevcut campaign metadata'sında zaten canonical bir tarih varsa onu koru.

Exact campaign date mevcut değilse V1 deterministik default:

1 Mirtul 1501 DR
09:00

kullan.

Campaign baseline:
1501 DR — Year of the Shining Mythal.

Current campaign start location:
Neverwinter.

Başlangıç timestamp'i bir kez oluşturulur ve campaign state içine kaydedilir.

Sonrasında gerçek sistem saatinden tekrar hesaplanmaz.

Campaign creation sonrasında başlangıç zamanı kendiliğinden değiştirilemez.

==================================================
3. AUTHORITATIVE TIME MODEL
==================================================

Campaign state içinde tek authoritative Campaign Time bulunmalıdır.

Minimum ihtiyaç:

- campaign date
- campaign clock time
- gerekli timezone/local-world convention
- gerekirse campaign-relative day index

Ayrı bir gerçek-zaman timer veya ayrı database clock oluşturma.

Mevcut world_state / campaign persistence mimarisini kullan.

Session isolation korunmalıdır.

Her GameSession kendi Campaign Time'ına sahip olmalıdır.

Modül seviyesinde ortak mutable clock kullanma.

==================================================
4. TIME ADVANCEMENT PRIMITIVE
==================================================

Tek ve güvenilir bir Python time-advance mekanizması oluştur.

Conceptually:

advance_campaign_time(
    duration,
    reason,
    source/action identity
)

Ancak bunu mevcut proje mimarisine uygun isimle uygula.

Bu primitive:

1. mevcut zamanı alır,
2. authoritative duration'ı uygular,
3. yeni zamanı hesaplar,
4. crossed event windows / due events'i değerlendirir,
5. gerekli canonical world changes'i uygular,
6. event/player-knowledge ayrımını korur,
7. aynı persistence/receipt transaction sınırında kaydeder.

TIME ADVANCEMENT EVENT'LERİN KENDİSİ TARAFINDAN YAPILMAZ.

Örneğin:

18:00
→ Event başladı
→ Campaign Time +30 dakika

YAPMA.

Doğru:

18:00
→ başka gameplay action zamanı +30 dakika ilerletti
→ event sistemi yeni zamanı değerlendirdi.

==================================================
5. IDEMPOTENCY
==================================================

Mevcut action receipt/idempotency sistemini yeniden kullan.

Aynı request iki kez gelirse:

İlk:
18:00 → 18:10

İkinci:
AYNI RESULT

olmalıdır.

18:10 → 18:20 olmamalıdır.

Aynı action ID farklı request ile kullanılırsa mevcut conflict/409 davranışı korunmalıdır.

Time advancement receipt'i persistence ile aynı authoritative transaction sınırında olmalıdır.

Event resolution da idempotent olmalıdır.

Aynı event aynı request/retry nedeniyle ikinci kez canonical state değiştiremez.

Yeni, paralel bir idempotency sistemi oluşturma.

==================================================
8. ACTIVE TASKS
==================================================

Campaign Time V1 active task sürelerini desteklemelidir.

Ancak komple generic quest/task engine oluşturma.

Task için minimum authoritative duration model oluştur.

Örnek:

Player:
"Bir saat araştırıyorum."

Bu:

"otomatik olarak 60 dakika geçir"

anlamına gelmez.

Oyuncunun belirttiği süre bir time budget / upper limit olabilir.

Python task resolution sonucunu belirler.

Örneğin:

requested limit = 60 min
actual task duration = 6 min
result = success

Campaign Time:

18:00 → 18:06

olmalıdır.

18:54 dakika boşa geçirilmez.

Task daha uzun sürecekse oyuncunun belirttiği limitte durabilir:

18:00 → 19:00

ve sonuç:

"Aradığını hâlâ bulamadın; daha fazla araştırabilirsin."

olabilir.

Task gerçekten 3 dakika sürüyorsa:

3 dakika.

Task gerçekten 25 dakika sürüyorsa:

25 dakika.

UNIVERSAL "DC = X dakika" formülü oluşturma.

Süre ile zorluk aynı şey değildir.

D20 yalnız meaningful uncertainty varsa atılır.

Örnek:

"Kapıyı açıyorum."

→ gereksiz check yok.

"Masadaki açık mektubu alıyorum."

→ gereksiz check yok.

"Gizli bölmeyi araştırıyorum."

→ meaningful uncertainty varsa check.

Natural 20 / natural 1 Core Resolution kurallarına göre çözülsün.

Nat 1 otomatik komik felaket değildir.

Nat 20 Qwen tarafından icat edilmiş ekstra mechanics üretmez.

Task completion sonrası yalnız gerçek elapsed duration Campaign Time'a eklenir.

==================================================
10. SCHEDULED WORLD EVENTS
==================================================

Scheduled event ile mevcut ambient event sistemini birbirine karıştırma.

Scheduled event için küçük, kalıcı ve Python-authoritative bir model oluştur.

Minimum concept:

- event_id
- window_start
- window_end
- location/scope
- prerequisites
- behavior type
- status
- canonical resolution/result
- player observation/knowledge state gerektiğinde

Event behavior türleri:

NON_INTERRUPTIVE
INTERRUPTIVE
OBSERVABLE

NON_INTERRUPTIVE:
- world state değişebilir,
- oyuncunun mevcut action'ını otomatik bölmez.

INTERRUPTIVE:
- yalnız gerçek encounter/interaction oluştuğunda action'ı etkileyebilir.
- yalnızca event window'ının overlap etmesi oyuncuyu otomatik durdurmaz.

OBSERVABLE:
- uygun konum/bağlam varsa oyuncu olayı fark edebilir.

29. TEST STRATEJİSİ
==================================================

TESTLERİ GEREKSİZ YERE ŞİŞİRME.

Önceki projede yaşadığımız gibi yüzlerce yeni test ekleyip işi uzatma.

Yalnız Campaign Time değişikliklerini doğrudan doğrulayan hedefli testler ekle.

En az şu kritik senaryolar:

1. First scene → deterministic Campaign Time creation.
2. Save/resume → exact same Campaign Time.
3. Server restart → Campaign Time does not advance.
4. Same time-advance action retry → no double advance.
5. Same event retry → no duplicate event resolution.
6. Active task completes earlier than requested time budget.
7. Explicit wait advances exactly requested duration.
8. Scheduled event window can be encountered inside the window.
9. Long action crossing an event window does not retroactively interrupt the player.
10. Missed event remains canonical and can leave aftermath.
11. Hidden event does not leak through API/journal/Qwen context.
12. Travel stage advances authoritative time.
13. Travel Event Dice has occurrence/type/disposition separation.
14. No Event is a valid travel result.
15. Travel event can interrupt only through actual encounter/resolution.
16. Combat round advances Campaign Time once by 6 seconds.
17. Combat does not create an automatic post-combat time skip.
18. Normal death rollback restores Campaign Time to combat checkpoint.
19. Normal death rollback preserves RNG/action receipts according to existing rules.
20. Frontend cannot directly mutate Campaign Time.

Bunların dışında test yalnızca gerçek regression riskini hedefliyorsa eklenebilir.

Mevcut ilgili testleri çalıştır.

Geniş test suite çalıştırmak değişiklik kapsamını anlamlı şekilde artırıyorsa önce hedefli suite ile doğrula.

Gerçek evidence olmadan "passed" deme.
