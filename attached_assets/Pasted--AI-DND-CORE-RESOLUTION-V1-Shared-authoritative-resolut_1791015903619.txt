# AI-DND — CORE RESOLUTION V1
# Shared authoritative resolution layer
# IMPLEMENTATION TASK

Artık AI-DND'nin Core Resolution katmanını oluşturuyoruz.

Bu görev Combat veya Quest sisteminin tamamını yazmak değildir.

Amaç:
Combat, Quest, Exploration, Skill Checks, Saving Throws ve ileride
diğer gameplay sistemlerinin kullanacağı ortak, deterministik ve
Python-authoritative çözüm omurgasını oluşturmak.

==================================================

==================================================

- optimistic gameplay sonucu oluşturamaz

5. DICE SYSTEM
==================================================

Mevcut güvenilir dice altyapısı varsa onu yeniden kullan.

Yeni bir ikinci RNG sistemi oluşturma.

Roll sonucu Python tarafından üretilmeli.

Bir resolution gerektiğinde sonuçta en azından:

- resolution_id
- roll type
- raw die roll(s)
- selected roll
- modifier breakdown
- total
- target/DC/AC
- outcome

bulunabilecek şekilde yapılandır.

Advantage:

- iki d20 at
- yüksek olanı kullan

Disadvantage:

- iki d20 at
- düşük olanı kullan

Hem Advantage hem Disadvantage varsa birbirini götürür
ve normal tek d20 kullanılır.

Birden fazla Advantage veya Disadvantage yeni zarlar üretmemeli.

==================================================
7. ABILITY CHECK
==================================================

Ability check:

d20
+
relevant ability modifier
+
relevant proficiency/circumstantial modifiers

sonucunu authoritative şekilde hesaplamalı.

Target:

DC

olmalı.

Total >= DC:

SUCCESS

Total < DC:

FAILURE

Ancak check gerekmeyen trivial/otomatik durumlarda
resolution zorlamak zorunda değilsin.

Mevcut engine'in doğrudan cevap verebildiği durumlar
Core Resolution'a zorla sokulmamalı.

10. ATTACK ROLL PRIMITIVE
==================================================

Combat henüz tamamen yazılmayacak.

Ancak ileride Combat'ın kullanacağı attack-roll primitive
Core Resolution içinde bulunmalı.

Attack roll:

d20
+
relevant ability modifier
+
proficiency bonus if applicable
+
circumstantial modifiers

vs

target AC

şeklinde Python tarafından çözülmeli.

Attack roll sonucu en az:

- attacker
- target
- d20 roll
- attack modifier breakdown
- attack total
- target AC
- outcome

taşıyabilmeli.

2024 kurallarındaki attack roll için doğal 20 / doğal 1 davranışı
yalnızca attack roll bağlamında uygulanmalı.

GENEL ability check veya saving throw için kendi başına
"natural 20 = automatic success" veya
"natural 1 = automatic failure" gibi kurallar uydurma.

Kuralları yüklenmiş 2024 kaynaklardan doğrula.

==================================================
11. STATE TRANSITION BOUNDARY
==================================================

Core Resolution sonucu ile state mutation'ı birbirine karıştırma.

Tercih edilen sınır:

Intent / Action
→ validation
→ Core Resolution
→ structured ResolutionResult
→ validated StateTransition
→ canonical state commit

Core Resolution kendi başına model prose'una göre state değiştirmemeli.

Bir state değişikliği gerekiyorsa yalnızca Python tarafından
doğrulanmış transition üzerinden uygulanmalı.

Örneğin:

resolution sonucu SUCCESS oldu diye otomatik olarak
"her zaman quest tamamla" veya "item ver" gibi genel davranış
ekleme.

State transition, ilgili gameplay sisteminin yetkisi olmalı.

Core Resolution sonuç üretir.

Combat Combat state'ini yönetir.

Quest Quest state'ini yönetir.

Inventory Inventory state'ini yönetir.

Bu separation korunmalı.

==================================================
12. IDEMPOTENCY
==================================================

Aynı player action / resolution ikinci kez işlendiğinde
ikinci kez zar atılmamalı veya ikinci kez state mutation
oluşmamalı.

Mevcut action/turn/request ID mekanizması varsa onu kullan.

Yeni ve paralel bir kimlik sistemi oluşturma.

Retry durumunda aynı authoritative resolution sonucu
yeniden kullanılabilmeli.

Bu özellikle ileride:

- browser retry
- API retry
- network retry
- model retry

gibi durumlarda aynı mekanik sonucun iki kez uygulanmasını
engellemek için korunmalı.

FINAL PRINCIPLE
==================================================

Oyuncu:

"Kapıyı açmayı deniyorum."

Qwen gerekirse bunu:

ACTION = INTERACT_WITH_DOOR

olarak anlayabilir.

Ama bundan sonrası Python'dur:

→ Kapı gerçekten var mı?
→ Oyuncu oraya erişebilir mi?
→ Check gerekiyor mu?
→ Hangi ability?
→ Hangi skill?
→ Hangi modifier?
→ Advantage/Disadvantage var mı?
→ DC kaç?
→ Zar kaç?
→ Sonuç ne?
→ State değişti mi?
→ Canonical event ne?

Qwen yalnızca bundan sonra:

"Kapının eski kilidi direniyor..."

gibi çözülmüş gerçeği anlatabilir.

PYTHON RESOLVES.
QWEN NARRATES.
FRONTEND PRESENTS.

Bu Core Resolution V1'in temel prensibidir.
