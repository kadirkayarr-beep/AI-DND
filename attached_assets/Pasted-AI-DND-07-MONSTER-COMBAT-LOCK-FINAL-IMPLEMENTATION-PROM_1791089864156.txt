- locations it knows

- exact secret vulnerabilities
- hidden trap locations

Python may know the entire canonical state.

18. OBSERVATION MEMORY
==================================================

The monster may remember events it actually observed.

- "The fighter used a longsword."
- "The cleric healed the rogue."
- "The invisible creature was last seen near the doorway."
- "My attack dealt unusually little damage."
- "My ally was dropped."

This is not full campaign memory.

It is combat-local tactical memory.

It must be persisted if the combat state is persisted and if the
information changes future canonical decisions.

Do not create narrative memory entries for every AI decision.

==================================================
19. HIDDEN RESISTANCE DISCOVERY
==================================================

If the monster observes a result that reveals something:

Do not reveal exact mechanics unless the monster could reasonably infer
them.

The mechanical resolver remains authoritative.

The AI's belief may be:

- unknown
- suspected
- known
- disproven

rather than always knowing exact values.

==================================================
28. CONTROLLED RANDOMNESS
==================================================

Monster decisions should not be completely deterministic if multiple
reasonable options exist.

Use the authoritative Python RNG when randomness is appropriate.

Do NOT create a second independent Monster RNG system.

Do NOT use:

- browser randomness
- Qwen randomness
- timestamps
- hashes
- arbitrary pseudo-random strings.

A good pattern is:

1. determine all legal candidates
2. eliminate clearly inferior/illegal candidates
3. score viable candidates
4. identify a small set of reasonable candidates
5. weighted-randomly choose among those candidates
6. persist the chosen result.

This gives variety without making monsters stupid.

==================================================
29. RANDOMNESS MUST NOT OVERRIDE LOGIC
==================================================

Randomness may choose among reasonable actions.

It must not select:

- impossible action
- out-of-range attack
- unavailable ability
- invalid target
- impossible movement
- exhausted resource.

Never:

"randomly pick any stat-block action."

Instead:

"randomly choose among currently sensible legal options."

==================================================
30. ANTI-REPETITION
==================================================

Avoid repetitive behavior when reasonable alternatives exist.

Example:

A dragon should not necessarily:

Breath
Breath
Breath
Breath

if the breath weapon is unavailable anyway.

A goblin should not always:

Attack target A

every turn when:

- another target becomes more dangerous
- movement changes
- morale changes
- an ally falls
- a better tactical option becomes available.

However:

DO NOT forbid repetition when repetition is actually sensible.

If a monster's best action is:

"Attack the nearest enemy"

it may do that multiple turns in a row.

Natural behavior is more important than artificial variety.

==================================================

+ legality
+ immediate tactical value

+ target accessibility
+ damage potential
+ condition potential
+ ally protection
+ resource efficiency
+ positional advantage
+ escape value
+ survival value
+ personality

Negative factors may include:

- dangerous exposure
- unnecessary resource consumption
- attacking a poor target
- abandoning a protected objective

==================================================
39. LEGENDARY ACTION TIMING
==================================================

A Legendary Action occurs immediately after another creature's turn,
according to the stat block.

Only legal Legendary Actions may be selected.

The monster cannot use Legendary Actions while Incapacitated if the rules
prevent it.

Do not let the AI spend multiple Legendary Actions in one illegal
window.

Respect:

- number of uses
- per-option restrictions
- start-of-turn recharge
- lair-specific values when authoritative state says the monster is in
  its lair.

==================================================
40. LEGENDARY RESISTANCE
==================================================

If a monster has Legendary Resistance:

the AI may choose whether to use it after a failed saving throw when the
stat block permits it.

Do not automatically use it on every failed save.

Evaluate:

- severity of effect
- remaining uses
- duration
- whether failure threatens survival
- whether the effect prevents future action
- monster personality
- encounter objective.

Examples:

A boss may spend Legendary Resistance to avoid:

- incapacitation
- paralysis
- banishment
- instant death.

It may accept a minor failed save to preserve resources.

The saving throw resolver remains authoritative.

Do not invent paths through impossible terrain.

==================================================
48. DISENGAGE
==================================================

If the monster wants to leave melee and would otherwise provoke
Opportunity Attacks:

it may consider Disengage when legal.

Do not automatically use Disengage every time it moves away.

Use tactical scoring.

#04 owns Action Economy.

Opportunity Attack resolution remains in the existing Reaction system.

==================================================
49. DASH
==================================================

If the monster needs to:

- escape
- chase
- close distance
- reach an objective

it may choose Dash.

The actual extra movement follows the existing rules.

Do not manually add arbitrary movement.

==================================================
50. DODGE
==================================================

A monster may choose Dodge when:

- survival is more important than attacking
- waiting is tactically valuable
- it is protecting an objective
- it has no useful attack
- it is buying time
- it is awaiting reinforcements.

Do not use Dodge merely because no attack exists.

==================================================
51. HIDE
==================================================

If the monster can legally Hide:

it may choose Hide.

Use the authoritative Hide rules.

Do not create a new stealth system.

The AI must not automatically become invisible merely because it
chooses Hide.

The existing rules determine success.

==================================================
52. HELP / SUPPORT
==================================================

If a monster can legally Help:

it may use Help to support an ally.

Examples:

- distracting a target
- helping an ally
- assisting a relevant check.

Do not assume every monster understands Help tactically.

Use Intelligence/personality/group behavior where appropriate.

==================================================
53. SEARCH
==================================================

A monster may use Search when:

- it lost a hidden target
- it suspects an invisible creature
- it needs to locate an enemy
- the environment requires investigation.

Use the authoritative Search/perception system.

Do not reveal hidden targets automatically.

==================================================
54. INFLUENCE / PARLEY
==================================================

Sapient monsters may attempt to:

- intimidate
- negotiate
- surrender
- demand terms
- threaten
- bargain
- ask for mercy.

If the monster wants to parley:

do NOT automatically end combat.

Create a canonical parley proposal.

The player gets to respond.

If the player rejects it:

combat continues.

If the player accepts:

existing combat-ending/social interaction flow handles the transition.

Do not let Qwen decide whether the player accepted.

==================================================
55. SURRENDER
==================================================

A monster may surrender when appropriate.

Surrender should be influenced by:

- personality
- intelligence
- morale
- survival instinct
- objective
- remaining allies
- enemy strength
- leadership
- fear.

Fanatical or desperate creatures may fight longer.

Cowardly creatures may surrender earlier.

Do not make surrender automatic at a fixed HP percentage.

==================================================
56. FLEEING
==================================================

Most creatures should not be forced to fight to the death.

Use the 2024 DMG fight-or-flight guidance as a behavioral baseline.

Important default triggers include:

- monster is Bloodied
- more than half its allies are dead or Incapacitated
- opposing side has not suffered comparable losses
- monster is Bloodied and Frightened
- defeat is obviously imminent.

These are behavioral triggers.

Do NOT create a new D&D condition called:

"Morale."

Use internal AI state only.

==================================================
57. BLOODIED
==================================================

2024 rules define Bloodied as:

current HP <= half maximum HP.

Use the authoritative HP state.

Do not create a separate HP field.

Do not alter HP because of Bloodied.

Bloodied is a tactical input.

Some monsters already have stat-block abilities that explicitly trigger
when Bloodied.

Those explicit mechanics take priority over generic AI behavior.

==================================================
58. MORALE DECISION
==================================================

When a monster becomes likely to flee:

evaluate:

- personality
- creature intelligence
- creature objectives
- remaining allies
- enemy strength
- current HP
- conditions
- escape route
- leader status
- mission importance.

Possible results:

CONTINUE_FIGHT
FLEE
PARLEY
SURRENDER
HOLD_POSITION
PROTECT_OBJECTIVE.

Do not make every monster roll a Wisdom save every turn.

Use the DMG's saving throw guidance only where an actual uncertainty
check is appropriate.

==================================================
59. MORALE RANDOMNESS
==================================================

If the outcome is genuinely uncertain:

a canonical Wisdom saving throw may be appropriate.

Use the existing authoritative saving throw resolver.

Use the existing RNG.

Do not create:

monster_morale_rng.

Do not ask Qwen.

Do not use a random number without rules context.

==================================================
60. ESCAPE DESTINATION
==================================================

When fleeing:

choose a destination based on known information.

Priority:

1. known safe location
2. known ally location
3. defensible position
4. nearest viable exit
5. maximum practical distance.

Do not invent a destination that does not exist.

If no escape path exists:

consider:

- fight
- surrender
- parley
- Dodge
- defend position.

==================================================
61. MONSTER OBJECTIVES
==================================================

Not every monster's objective is:

"KILL THE PLAYER."

Possible objectives:

- defend lair
- protect leader
- protect treasure
- delay intruders
- escape
- capture target
- steal object
- prevent alarm
- reach another room
- survive
- hold a doorway
- protect ritual
- retrieve item
- eliminate specific threat.

Objective data must come from:

- campaign canon
- encounter data
- explicit monster/campaign configuration.

Do not invent major campaign objectives during combat.

==================================================
62. CAPTURE VS KILL
==================================================

Some monsters may prefer:

- capture
- restrain
- knock out
- abduct
- interrogate.

Only if their canonical objective or behavior supports it.

Do not change attack mechanics.

The monster can choose an existing legal action that achieves the objective.

==================================================
63. UNCONSCIOUS PLAYER TARGETS
==================================================

A monster may recognize that a player character is Unconscious.

The AI must NOT automatically attack unconscious characters.

It should consider:

- whether finishing the target is tactically necessary
- whether another threat exists
- monster personality
- cruelty
- objective
- intelligence
- survival pressure
- opportunity.

Examples:

A ruthless assassin may finish an unconscious target.

A hungry beast may attack the nearest active threat instead.

A guard may ignore a downed intruder while attacking active threats.

A creature defending a leader may ignore a downed enemy.

This is behavioral choice.

If an attack occurs:

#06 resolves it.

#08 owns the resulting death state.

==================================================
64. TARGET PRIORITY AFTER A PLAYER DROPS
==================================================

When a target reaches 0 HP:

re-evaluate the battlefield.

Do not blindly repeat:

same target.

The monster may:

- attack another active threat
- protect itself
- retreat
- finish the downed target
- pursue another objective.

The choice must be contextual.

==================================================
65. MONSTER CONDITIONS
==================================================

The AI must respect existing conditions.

At minimum:

- Blinded
- Charmed
- Deafened
- Frightened
- Grappled
- Incapacitated
- Invisible
- Paralyzed
- Petrified
- Poisoned
- Prone
- Restrained
- Stunned
- Unconscious.

Do not duplicate condition rules.

Query the authoritative condition system.

==================================================
66. INCAPACITATED MONSTERS
==================================================

An Incapacitated monster cannot take actions where the rules prohibit
them.

Do not ask the AI what an Incapacitated monster wants to do.

Return a deterministic no-action result.

Do not advance the turn incorrectly.

==================================================
67. STUNNED / PARALYZED / UNCONSCIOUS
==================================================

The AI must respect their actual mechanical restrictions.

Do not allow:

- movement when prohibited
- actions when prohibited
- reactions when prohibited
- legendary actions when prohibited.

Do not implement condition effects inside Monster AI.

==================================================
68. MONSTER TRAITS
==================================================

Traits can influence decisions.

Examples:

- Magic Resistance
- Blood Frenzy
- Berserk
- Pack Tactics-like effects if present
- Regeneration
- Fire Aura
- Legendary Resistance
- special movement
- special defensive behavior.

The AI must read the actual trait.

Do not generalize from monster type.

Do not assume:

all dragons behave identically.

Do not assume:

all undead never flee.

Do not assume:

all beasts are unintelligent.

Use actual stat block data.

==================================================
69. TRAIT TRIGGERS
==================================================

Some traits trigger automatically.

If a trait says:

"Whenever..."

or

"At the start of..."

or

"when Bloodied..."

that mechanic should be resolved by the authoritative mechanic system.

#07 should not convert every trait into a voluntary AI decision.

Example:

If a trait automatically causes a reaction:

do not ask the AI whether the trait exists.

If a trait says:

"the monster can choose..."

then #07 may choose.

==================================================
70. BERSERK / ENRAGED BEHAVIOR
==================================================

If a monster has an explicit trait such as Berserk:

the trait controls behavior.

Do not replace it with generic morale.

Example:

if the stat block explicitly says:

"attacks the nearest creature"

then the AI must obey that rule.

A generic personality cannot override an explicit trait.

==================================================
71. REACTIVE TACTICS OUTSIDE CURRENT TURN
==================================================

If the project already supports nearby NPC/monster awareness:

#07 may provide a behavior decision for alerted monsters.

Possible reactions:

- investigate
- ambush
- fortify
- hide
- flee
- join allies.

Do NOT build a new world simulation system.

Do NOT build a new alarm network.

Do NOT create new world events.

Use existing campaign/event infrastructure.

If this infrastructure is not currently available:

provide a clean extension point and report it as out of scope.

==================================================
72. COMBAT REINFORCEMENTS
==================================================

If an existing encounter causes another monster to join:

use the existing Combat Lifecycle.

The new monster must:

- receive a canonical participant ID
- receive its stat block
- receive valid Initiative according to #05
- enter the existing combat state
- receive a Monster AI state.

Do not create a second combat system.

Do not reroll existing participants.

==================================================
73. NEW MONSTER ENTRY
==================================================

When a monster joins an existing combat:

do not modify existing initiative results.

Only the joining monster's initiative may be resolved according to #05.

Do not reorder existing participants.

Do not restart the round.

==================================================
74. MONSTER GROUP LEADERS
==================================================

If a monster group has an authoritative leader:

the leader may influence:

- target priority
- retreat
- parley
- protection
- group positioning.

Do not make the leader telepathically control all monsters.

Use actual communication capability.

==================================================
75. LEADER DEATH
==================================================

If a leader dies or becomes incapacitated:

re-evaluate group behavior.

Possible results:

- panic
- retreat
- frenzy
- continue
- surrender
- protect the body
- attack the killer.

Do not hardcode one universal response.

Use personality + relationships + objective.

==================================================
76. PLAYER AGENCY
==================================================

Monster AI must never control the player.

The monster may:

- attack
- move
- flee
- surrender
- parley
- threaten
- negotiate.

But it cannot decide:

- player accepts surrender
- player follows a fleeing monster
- player agrees to parley
- player drops weapon
- player becomes frightened
- player changes target.

Those remain player/canonical mechanics.

==================================================
77. PARLEY HANDOFF
==================================================

If a monster initiates parley:

return a structured:

PARLEY_PROPOSED

result.

The narration layer may describe:

"The creature lowers its weapon and demands..."

But the canonical state must record only the verified proposal.

The player must respond.

No automatic combat termination.

==================================================
78. FLEE HANDOFF
==================================================

If a monster chooses to flee:

return:

FLEE_DECLARED

plus:

- monster
- destination
- movement intent
- reason code.

Then normal movement/reaction systems resolve what happens.

Do not teleport the monster out of combat.

Do not automatically end combat until the existing Combat Lifecycle
determines that the combat has actually ended.

==================================================
79. MOVEMENT AND OPPORTUNITY ATTACKS
==================================================

If a fleeing monster leaves enemy reach:

the existing Reaction / Opportunity Attack system handles the result.

#07 must not manually roll an opportunity attack.

#06 resolves the attack.

#04 owns the Reaction resource.

==================================================
80. MONSTER ACTION RESULT CONTRACT
==================================================

Create or extend a structured MonsterDecision result.

Conceptually:

MonsterDecision:

- decision_id
- action_id
- combat_id
- actor_id
- turn_id
- round
- decision_type
- capability_id
- target_ids
- movement_intent
- destination
- action_source
- resource_used
- reason_code
- behavior_profile
- objective
- perception_snapshot_id
- RNG metadata if randomness was consumed
- receipt metadata.

Do not store hidden chain-of-thought.

==================================================
81. DECISION RECEIPTS
==================================================

Monster decisions must be idempotent.

If the same monster-turn request is replayed:

do NOT:

- choose another action
- reroll decision randomness
- spend another resource
- move twice
- attack twice
- consume Legendary Action twice
- consume Recharge resource twice
- apply effects twice.

Return the original canonical result.

Use the existing receipt system.

Do NOT create a parallel persistence/idempotency architecture.

==================================================
82. MONSTER TURN TRANSACTION
==================================================

A monster turn should be transactional where existing architecture
supports transactions.

If resolution fails after:

- movement
- resource consumption
- attack
- condition application

the existing rollback system must restore the appropriate state.

Do not leave:

- partial movement
- partial resource consumption
- duplicate attacks
- duplicate conditions
- incorrect current actor
- incorrect RNG
- incorrect receipts.

==================================================
83. RNG
==================================================

Use the existing authoritative RNG.

Monster AI may consume RNG for:

- Recharge rolls
- morale saves
- weighted action selection
- other explicit random monster mechanics.

Do not create:

monster_rng
AI_rng
behavior_rng

as independent authoritative RNG systems.

All randomness must be auditable.

==================================================
84. RNG REPLAY
==================================================

When a monster decision consumes RNG:

the result must be persisted/replayed through the existing receipt system.

Replay must NOT reroll the decision.

Save/load must NOT change the chosen action.

A monster cannot:

save
reload
and suddenly decide to flee instead of attack

because RNG was restored incorrectly.

==================================================
85. RNG AND DECISION VARIETY
==================================================

Randomness should create variety.

It should not create nonsense.

Example:

If a goblin has:

- attack target A: score 90
- attack target B: score 88
- flee: score 20

the system may choose A or B.

It should not normally choose flee.

If:

- attack A: 20
- flee: 95

flee should dominate.

This is an internal decision policy.

Do not expose numeric scores to players.

==================================================
86. NO PERFECT TACTICIAN
==================================================

The Monster AI must not behave like an omniscient chess engine.

It should make believable decisions using:

- available information
- intelligence
- role
- personality
- objectives
- current danger.

Low-Intelligence creatures should not automatically perform
high-complexity tactical plans.

High-Intelligence creatures may:

- focus threats
- exploit observed weaknesses
- reposition
- protect allies
- use resources intelligently.

But even intelligent monsters should not receive hidden information.

==================================================
87. INTELLIGENCE / WISDOM / CHARISMA
==================================================

Ability scores may influence tactical complexity.

Very low Intelligence:

prefer simple behaviors.

Average Intelligence:

basic tactical adaptation.

High Intelligence:

more complex target selection and resource use.

Wisdom may influence:

- threat awareness
- perception
- instinct
- caution.

Charisma may influence:

- leadership
- intimidation
- parley
- group influence.

These are AI heuristics.

They do NOT modify the actual ability scores.

==================================================
88. MONSTER EMOTIONAL STATES
==================================================

Do not create a giant emotion engine.

If needed, use a small internal tactical state:

- Calm
- Aggressive
- Alarmed
- Frightened
- Desperate
- Retreating
- Surrendering.

Only create these when they are useful.

Conditions remain authoritative.

Do not create:

"Angry +3"

or similar fake D&D statistics.

==================================================
89. NO HIDDEN POWER SCALING
==================================================

Monster AI must never compensate for poor tactics by secretly changing:

- attack bonus
- AC
- HP
- damage
- saving throws
- movement
- recharge chance.

Difficulty must come from:

- actual stat block
- actual tactics
- actual environment
- actual numbers.

Never cheat.

==================================================
90. NO DYNAMIC HP CHEATING
==================================================

Do not increase or decrease monster HP simply because combat is:

- too easy
- too hard
- boring
- repetitive.

Do not secretly change AC.

Do not secretly change damage.

Do not secretly grant extra abilities.

DMG guidance may inspire behavior such as:

- surrender
- retreat
- reposition
- reinforcement

but does NOT authorize invisible mechanical cheating.

==================================================
91. MONSTER DEATH BOUNDARY
==================================================

#07 must NOT redesign monster death.

When a monster reaches 0 HP:

Do not create:

- monster death saves
- monster stable state
- monster unconscious recovery
- second death engine.

#08 remains the owner of the Death System.

==================================================

#07 may produce:

- FLEE
- SURRENDER
- PARLEY
- CONTINUE.

But #03 Combat Lifecycle determines whether combat actually ends.

Do not directly close combat merely because:

"the monster decided to flee."

The lifecycle must verify whether:

- all hostile participants fled
- all enemies are defeated
- all sides agreed to end combat
- another combatant remains.

==================================================
93. MULTIPLE MONSTERS FLEEING
==================================================

- parley
- defend
- desperate action.

FLEE

when no movement is possible.

==================================================
95. MONSTER ACTION AVAILABILITY
==================================================

- actor alive/active
- current actor
- condition restrictions
- action resource
- target validity
- range
- position
- resource availability
- recharge
- usage limits
- stat-block prerequisites.

- Dodge
- Dash
- movement
- defensive action
- Ready
- no action

depending on actual state.

Do not fabricate an action.

==================================================

==================================================

If the AI cannot find a useful attack:

1. useful special ability
2. movement
3. defensive action
4. objective action
5. Dash
6. Dodge
7. Ready
8. no action.

This is a fallback order, not a hardcoded universal priority.

==================================================

==================================================

If Monster AI somehow produces an invalid action:

- silently choose another target
- reroll until valid
- call Qwen
- mutate state partially.

1. reject invalid decision
2. record deterministic failure
3. use a deterministic fallback if the architecture allows fallback
4. ensure no invalid state mutation occurred.

The fallback must itself be authoritative and idempotent.
