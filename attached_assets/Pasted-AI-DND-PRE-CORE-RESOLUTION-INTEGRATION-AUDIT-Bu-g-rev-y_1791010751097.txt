AI-DND — PRE-CORE-RESOLUTION INTEGRATION AUDIT

Bu görev yalnızca READ-ONLY denetimdir.

Hiçbir dosyayı değiştirme.
Hiçbir kod yazma.
Hiçbir dosyayı silme.
Commit, push, reset, rebase, merge yapma.
Smoke test çalıştırma.
Canlı model/Ollama çağrısı yapma.

Amaç:
Core Resolution System'e başlamadan önce mevcut karakter oluşturma,
species ability, persistence, API ve gameplay temelinin gerçekten
hangi durumda olduğunu kesin olarak tespit etmek.

1. Git durumu
- current branch
- HEAD
- origin/main
- git status --short
- origin/main..HEAD farkı
- çalışma ağacındaki tüm tracked/untracked değişiklikler
- özellikle son raporda belirtilen Aasimar/Goliath/Orc değişikliklerinin
  tam dosya listesini çıkar.

2. Son değişikliklerin kapsamı
Her değişen dosyanın:
- neden değiştiğini
- gameplay açısından ne yaptığını
- Core Resolution ile doğrudan veya dolaylı ilişkisini
  kısa şekilde belirt.

3. Character Creation
Aşağıdakileri kaynak koddan doğrula:
- class
- background
- species
- ability scores
- skills
- feats
- spells
- equipment
- identity/origin
- HP
- AC
- fighting style
- persistence

4. Species
Aasimar, Goliath ve Orc için:
- motor çözümü
- API contract
- persistence
- frontend representation
- usage/rest reset
- save/load
- mevcut 2014 Half-Elf/Half-Orc uyumluluğu

5. Core Resolution hazırlığı
Mevcut kodda zaten bulunan:
- d20 checks
- DC
- modifiers
- proficiency
- advantage/disadvantage
- critical
- saving throws
- attack rolls
- damage
- healing
- resistance
- temporary HP
- conditions
- duration
- turn/round timing

mekanizmalarını yalnızca mevcut koddan tespit et.

Bunlardan hangileri gerçek Python-authoritative çözüm,
hangileri yalnızca UI/test/mock seviyesinde, açıkça ayır.

6. Combat
Combat'ın bugün gerçekten desteklediği mekanikleri listele.
Henüz desteklenmeyenleri de listele.

7. Quest
Quest sisteminin bugün desteklediği mekanikleri listele.
Core Resolution ile bağlantılarını belirt.

8. Memory
Oyuncunun yaptığı:
- zar sonucu
- savaş
- NPC etkileşimi
- görev
- item değişimi
- species ability
- önemli dünya olayı

gibi olayların hangilerinin kalıcı hafızaya/kampanya günlüğüne
girdiğini doğrula.

9. Regression
Mevcut testleri çalıştırma.
Sadece mevcut test dosyalarını inceleyerek:
- hangi alanların test edildiğini
- hangi alanların test edilmediğini
listele.

10. Manuel test boşlukları
Özellikle gerçek tarayıcı oynanışında test edilmesi gereken
en önemli 10 senaryoyu belirle.

11. SONUÇ
Raporu şu üç başlık altında bitir:

READY:
Core Resolution'a geçmeden önce hazır olanlar.

RISK:
Core Resolution'a başlamadan önce bilmemiz gereken mevcut
eksikler veya entegrasyon riskleri.

BLOCKER:
Core Resolution'a başlamadan önce mutlaka çözülmesi gereken
gerçek bir blocker varsa belirt.

Önemli:
Eksik bir mekanizma gördüğünde kendin yeni mimari icat etme.
Önce mevcut kodu raporla.

Bu görev sonunda yalnızca rapor ver.
Kod değişikliği yapma.
