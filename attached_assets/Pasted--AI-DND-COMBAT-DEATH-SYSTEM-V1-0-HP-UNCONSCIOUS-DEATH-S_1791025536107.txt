# 2. D&D 2024 DEATH MODELİ

2024 PHB kurallarını esas al.

Player Character için:

HP > 0
→ normal

HP = 0
→ Unconscious

0 HP'de karakter hemen "dead" değildir.

Her oyuncu turunun başında karakter 0 HP ile unconscious durumdaysa
bir Death Saving Throw çözülür.

Death Saving Throw:

- d20
- ability modifier YOK
- proficiency bonus YOK
- Advantage/Disadvantage yalnızca gerçekten doğrulanmış bir oyun etkisi
  tarafından verilmişse uygulanabilir
- 10+ = success
- 9 veya altı = failure
- natural 1 = 2 failures
- natural 20 = karakter 1 HP kazanır ve death-save süreci sona erer
- 3 successes = Stable
- 3 failures = Dead

Success/failure sayaçları:

- birbirinden bağımsız tutulur
- karakter Stable olduğunda sıfırlanır
- karakter herhangi bir HP kazandığında sıfırlanır
- karakter tekrar 0 HP'ye düşerse yeni death-save süreci başlar

Bu davranışı Python çözmelidir.

Qwen sonucu belirleyemez.

# 3. 0 HP'DE ALINAN HASAR

Karakter 0 HP'deyken hasar alırsa:

- normal damage → 1 Death Saving Throw failure
- Critical Hit damage → 2 Death Saving Throw failures
- damage karakterin HP maximum değerine eşit veya daha fazlaysa → DEAD

Bu kurallar mevcut damage resolution'ın üzerine bağlanmalı.

Aynı hasarı iki kez uygulama.

Mevcut combat action idempotency mekanizmasını koru.

# 4. UNCONSCIOUS DAVRANIŞI

0 HP olan player character:

- Unconscious
- Incapacitated
- Prone
- Speed = 0
- Attack rolls against character = Advantage
- Strength saving throws = automatic failure
- Dexterity saving throws = automatic failure
- karaktere 5 feet içinden isabet eden attack roll = Critical Hit

Unconscious karakter normal oyuncu eylemleri gerçekleştiremez.

Şimdilik genel bir Condition System yazma.

Eğer projede mevcut condition altyapısı varsa onu kullan.

Yoksa yalnızca Death/Unconscious için gereken minimum authoritative state'i ekle.

Şunları BU ÇALIŞMAYA EKLEME:

- tam condition sistemi
- movement sistemi
- spell condition sistemi
- exhaustion sistemi
- concentration sistemi
- genel combat action sistemi

Bunlar sonraki Combat fazlarının konusudur.

# 5. STABILIZED DURUM

# 6. DEATH CHECKPOINT

Şimdi AI-DND'ye oyun tasarımına özgü bir özellik ekliyoruz.

Normal Mode'da Combat başladığı anda:

PRE-COMBAT CHECKPOINT oluştur.

Bu checkpoint oyuncuya manuel save olarak gösterilmemeli.

Checkpoint en azından güvenilir şekilde şunları kapsamalı:

- character HP/state
- combat state
- initiative/turn/round state
- combat participants
- campaign state
- inventory/equipment değişiklikleri
- combat sırasında oluşabilecek diğer authoritative state değişiklikleri
- gerekli campaign journal/persistence state

Amaç:

Player normal mode'da gerçekten öldüğünde oyunu combat başlamadan
önceki authoritative state'e geri döndürebilmek.

Bu bir "Qwen hikayeyi geri anlattı" mekanizması değildir.

Gerçek Python state rollback'udur.

# 7. NORMAL MODE

Normal Mode:

Death Save → 3 failures
→ DEAD

olduğunda:

1. Combat sona erer.
2. Pre-combat checkpoint restore edilir.
3. Combat sırasında oluşan state değişiklikleri geri alınır.
4. Player combat başlamadan önceki state'e döner.
5. Karakter tekrar oynanabilir durumda olur.
6. Ölüm kalıcı campaign canon olarak kalmaz.
7. Oyuncu aynı maceraya devam edebilir.

Buradaki "5–10 dakika önce" davranışını gerçek zamanlı bir rollback
olarak tasarlama.

Eğer mevcut world-time sistemi uygun değilse fiziksel oyun saatini
rastgele geri alma.

Authoritative rollback noktası:

COMBAT START SNAPSHOT

olmalıdır.

Narrative olarak UI/Qwen bunu "savaştan hemen önce" şeklinde sunabilir,
ancak Python state'i yalnızca gerçek checkpoint'e restore eder.

# 8. PERMADEATH MODE

Oyuncu campaign oluştururken:

NORMAL
veya
PERMADEATH

modlarından birini seçebilmeli.

Permadeath Mode'da:

3 Death Save failures
→ DEAD

olduğunda:

- checkpoint restore EDİLMEZ
- combat state rollback EDİLMEZ
- character status = DEAD
- death campaign canon olur
- ölüm persistent olarak kaydedilir
- save/resume sonrasında karakter DEAD kalır
- frontend karakteri canlıymış gibi gösteremez
- Qwen karakterin ölmediğini iddia ederek state'i değiştiremez

Bu modda "geri sar" seçeneği bulunmamalı.

# 9. IRONMAN MODE

Ayrıca üçüncü bir oyun modu destekle:

NORMAL
PERMADEATH
IRONMAN

IRONMAN:

- Permadeath davranışını kullanır.
- Death → no checkpoint rollback.
- Character DEAD olarak persistent hale gelir.
- Resurrection mekanikleri de devre dışıdır.

Yani:

NORMAL
→ death = rollback

PERMADEATH
→ death = permanent character death
→ normal D&D resurrection mechanics ileride kullanılabilir

IRONMAN
→ death = permanent character death
→ resurrection disabled

Önemli:

Resurrection sistemini şimdi IMPLEMENT ETME.

Sadece oyun modunun ileride resurrection mekaniklerine izin verip
vermediğini belirleyen authoritative flag/state oluştur.

# 12. IDEMPOTENCY

Death Save ve Death resolution mevcut action/resolution idempotency
kurallarıyla uyumlu olmalı.

Aynı resolution tekrar işlendiğinde:

- ikinci kez zar atılmamalı

- aynı resolution sonucu geri dönmeli

Aynı ID farklı bir resolution için kullanılırsa mevcut sistemdeki
conflict davranışı korunmalı.
