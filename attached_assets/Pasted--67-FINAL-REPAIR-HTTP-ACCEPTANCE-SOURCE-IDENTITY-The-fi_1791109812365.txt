============================================================

This distinction is mandatory.

The archive must clearly distinguish:

A) the local verifier source identity

from

B) the source/revision identity of the server being tested.

The local verifier fingerprint MUST NOT be presented as proof of the
remote server's revision.

If the server independently exposes no trustworthy revision/source
identity, explicitly record the server identity as:

- unknown
- unavailable
- unverified

or the equivalent established representation.

Do NOT invent a server revision.

Do NOT infer a remote revision from the local working tree.

The final evidence must make it impossible to mistake:

"verifier source fingerprint"

for:

"server source revision".

============================================================
SOURCE-CHANGE DETECTION
============================================================

Capture the verifier source fingerprint before execution.

Capture it again after execution.

If the source changed during the run:

- mark the archive accordingly
- preserve both fingerprints
- do NOT report the run as unchanged-source certified.

The acceptance result itself may still be preserved, but its evidence
must clearly state that source changed during capture.

If the source did not change:

- record matching before/after fingerprints
- explicitly mark the source as unchanged.

Do not silently discard failed or interrupted runs.
